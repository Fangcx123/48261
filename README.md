# 多媒体系统——工位四步通

基于安路 EG4S20BG256 FPGA 的图像显示与语音指导系统。系统从 FAT32 格式 TF 卡读取 BMP 图像和 WAV 音频，通过 HDMI 输出图像及叠加界面，并播放配套语音，实现四步工位操作指导。

系统以“准备、操作、对照、收尾”为内容组织方式，集成图像切换、缩略图预览、语音播放、字幕显示及参数设置功能。

## 1. 主要功能

- **图像显示**：读取四张 BMP 图卡，将不同分辨率的图像缩放至 640 × 480 显示区域。
- **多帧缓存**：利用 SDRAM 保存图像数据，支持图像预载、切换和后台加载。
- **缩略图预览**：生成四张图卡的缩略图，提供内容预览界面。
- **语音播放**：读取 48 kHz、16 位 PCM WAV 文件，支持指导语音播放与重播。
- **字幕与页面联动**：依据音频样本计数控制字幕显示和页面切换。
- **参数设置**：通过按键菜单调整亮度、对比度、音量及轮播间隔。
- **状态显示**：叠加页号、计时、播放状态及音频波形等信息。

HDMI 接口持续输出符合显示时序的图像信号，显示内容由静态图卡和动态叠加界面组成。

## 4. 系统实现

### 4.1 TF 卡文件读取

硬件逻辑完成 FAT32 文件定位及数据读取，将图像和音频文件分别送入对应解析模块。

BMP 读取链路解析图像头信息、行数据及对齐填充；WAV 读取链路解析音频格式与数据区，将 PCM 样本送入音频缓冲链路。

### 4.2 图像缩放与缓存

图像缩放模块采用最近邻采样，将支持的输入图像转换为显示所需的像素序列。

SDRAM 保存多幅图像。读写控制逻辑协调后台加载和显示读取，通过缓存状态及握手机制管理图像数据的有效性。

### 4.3 显示与跨时钟域控制

显示链路按 640 × 480 有效分辨率组织像素输出，并叠加菜单、字幕、状态和波形信息。

图像提交与参数更新通过跨时钟域同步及握手机制传递。音频数据通过异步 FIFO 进行缓冲与跨时钟域传输。

### 4.4 语音、字幕与页面联动

系统以音频样本计数作为字幕与页面事件的时间依据。样本计数到达预设边界时，更新字幕或触发图卡切换。

在 48 kHz 采样率下，样本位置与时间的关系为：

```text
时间（秒）= 样本计数 / 48000
```

该方式使字幕及页面事件与音频播放进度关联，避免使用独立计时器累计播放时间偏差。

## 5. 工程打开与构建

### 5.1 工程入口

在 Tang Dynasty 中打开：

```text
src/td_project_workstation_v10/HDMI1.4b_Transmitter_v1.0.al
```

顶层模块：

```text
top
```

顶层源文件：

```text
src/user_source/hdl_source/top_tf_hdmi_audio.v
```

约束目录：

```text
src/user_source/constraints_source/
```

打开工程后，应确认目标器件、源文件引用、引脚约束和时序约束均已正确加载。

### 5.2 完整构建流程

比赛工程的完整构建包含：

1. 综合。
2. 布局布线，布局种子为 5。
3. 保持时间 ECO 修复。
4. 时序检查。
5. 从修复后的数据库生成最终 bit 文件。

对应的原工程脚本为：

```text
verification/workstation_v11/build_v11.tcl
verification/workstation_v11/fix_hold_v11.tcl
verification/workstation_v11/bitgen_v11.tcl
```

原工程部分脚本使用开发环境中的固定路径。首次在其他电脑运行前，应检查并调整脚本中的工程路径及 TD 工具路径。

仅在图形界面执行一般编译，不会自动执行上述脚本中的保持时间 ECO 修复步骤。最终下载文件应来自完成修复并通过时序检查的构建结果。

### 5.3 已有发布文件

```text
release/workstation_v11_read_fix_20261029/
```

其中包含发布 bit 文件、最终时序报告、源码哈希及相关验证记录。

## 6. TF 卡资源准备

将 TF 卡格式化为 FAT32，并将以下文件放入卡根目录：

```text
PIC1.BMP
PIC2.BMP
PIC3.BMP
PIC4.BMP
AUDIO.WAV
```

保留上述文件名。

### 图卡

```text

```

| 文件 | 内容 | 分辨率 |

图卡均为 24 位无压缩、正高度 BMP。系统将其缩放至 640 × 480 显示区域。

配套语音位于：

```text

```

该文件为 48 kHz、16 位、单声道 PCM WAV，与工程中的字幕及页面切换样本点配套。

更换语音后，需要同步检查字幕时间边界及页面切换事件。

## 7. 验证方法

验证内容包括：

- FAT32 文件读取及异常场景处理。
- BMP 解析、缩放和像素数据比对。
- 图像缓存、后台加载及页面切换。
- 菜单、字幕和参数控制。
- WAV 数据解析、音频输出及页面事件。
- SDRAM 控制器与图像读写链路联合仿真。
- 综合、时序及源码一致性检查。

安装 Icarus Verilog 后，在仓库根目录的 WSL 或 Linux Shell 中运行，例如：

```sh
sh verification/workstation_v10/run_seven_fast.sh
sh verification/workstation_v10/run_control_tests.sh
sh verification/workstation_v10/run_video_tests.sh
sh verification/workstation_v11/run_system_ctrl.sh
```

部分验证入口存在跨目录依赖：

- 系统控制器联合仿真使用 `workstation_v10/sdram_gate.v`。
- 音频测试使用 `wav_v8/` 中的测试数据及生成脚本。
- FAT32 测试读取 `fat32_fixtures/` 中的扇区数据。

历史工程修改、诊断及发布脚本不属于统一测试入口；使用前应确认其输入文件与适用工程阶段。
